# Asset License and Provenance Policy

## Hard boundary

`assets/approved_cc0/` is reserved for assets licensed **CC0 1.0 Universal** with evidence that the specific downloaded source file is covered. This is a strict library boundary, not an aspiration.

“Free,” “royalty-free,” “commercial use allowed,” “free with attribution,” “personal and commercial use,” and “generated by a free plan” do not meet the CC0 admission rule.

## Four separate lanes

| Lane | May contain binary source files? | Runtime eligible? | Required record |
| --- | --- | --- | --- |
| `approved_cc0` | Yes | Yes, after project-level review | Complete CC0 ledger entry and captured license evidence |
| `candidates_needing_review` | Optional, preferably archive only | No | Source URL, reason for review, status |
| `generated_reference_only` | No final source asset by default | No | Tool, creation ID, terms, prompt/input provenance, review state |
| `paid_reference_only` | No vendor source files unless redistribution is explicitly granted | No | Vendor URL, purchaser/licensee, permitted projects, prohibited redistribution notes |

## Required proof for approval

Every approved entry must state:

1. Exact source page and creator/publisher.
2. Exact upstream archive filename and SHA-256 after download.
3. Exact internal source path(s) admitted from that archive.
4. License identifier: `CC0-1.0`.
5. License URL and a locally captured upstream license note in `licenses/upstream/`.
6. Retrieval date and reviewer.
7. Confirmation that commercial use and redistribution are permitted.
8. Technical intake result: import format, units, pivot, collision, material count, texture footprint, LOD state, and visual semantics.
9. Destination and use tags.

Missing evidence means `candidate`, never `approved`.

## Project-specific derivatives

CC0 raw assets may be transformed for each game. Each project retains its own transformed file, manifest entry, source link, and visual review. Do not write project-specific culture, race, named-place, or character metadata into a neutral source entry.

## Generated and paid sources

Generated outputs are not assumed CC0. They remain reference-only until their applicable tool terms, input provenance, and project admission are recorded. Paid store assets are recorded as references with their license constraints; they are not uploaded to this shared repository merely because one contributor purchased them.

## License conflicts

When a source page, archive, embedded README, and marketplace listing disagree, treat the asset as quarantined. Preserve the evidence and resolve the conflict before any technical work or redistribution.

## Removal and correction

If later evidence invalidates an approval, immediately change the ledger status to `quarantined`, remove it from consuming project manifests, and record the reason. Do not rewrite history or silently delete the provenance record.
